# 配置和故障排查

## 两份配置的职责

DSH 插件设置负责找到 Python、后端配置，以及决定是否通过 QQ 发送。

| 插件字段 | 默认 / 用途 |
|---|---|
| `dataDir` | `DSH_HOME/singing` 或 `~/.dsh/singing` |
| `configFile` | 数据目录下的 `backend.json` |
| `pythonPath` | 数据目录下虚拟环境的 Python |
| `delivery` | `auto`；也可选 `file`、`qq` |
| `toolName` | `sing_song`；与已有插件冲突时可改 `sing_song_local` |
| `timeoutMs` | 0：不设插件总处理超时；正数为毫秒，主机自身超时仍适用 |

`backend.json` 管理本地模型和文件。其相对路径按配置文件所在目录解析，示例见仓库根目录的 `backend.example.json`。

| 后端字段 | 用途 |
|---|---|
| `dataDir` | 任务、成品、定位和音源缓存目录 |
| `modelsDir` | 已校验模型目录 |
| `vendorDir` | 固定版本并应用补丁的 Seed-VC |
| `referenceAudio` | 用户提供的参考说话音频 |
| `outputDir` | 允许生成 MP3 的目录；QQ 发送还需符合 OneBot 的目录限制 |
| `ffmpeg` | FFmpeg 路径或 PATH 中的命令名 |
| `allowedSourceRoots` | 可通过 `source_path` 读取的音频目录，默认空列表 |
| `comfyUrl` | 可选的本机 ComfyUI 地址；默认不连接 |
| `unloadComfy` | 队列为空时是否允许卸载 Comfy 模型，默认 `false` |

本地音频导入仅接受配置目录内、最大 100 MB 的受支持音频文件。路径会解析符号链接后再校验。该目录中的音频可能被有权调用唱歌工具的会话使用，请只放准备提供给机器人的素材。

## 常见问题

- **找不到 Python / 后端未配置**：运行安装器，检查插件的三个路径是否指向同一份数据目录。
- **Reference voice 未就绪**：设置 `referenceAudio`；文件需可解码、时长 3–120 秒。
- **CUDA 不可用**：确认驱动和 PyTorch 安装类型。使用 `--torch cpu` 可安装 CPU 版，但长片段可能非常慢。
- **找到了网页却无法唱**：看工具说明的失败阶段。标题/版本校验失败不等于禁止下载；平台拒绝访问时稍后重试。
- **没有 qq_send_voice**：启用现有 OneBot 的语音发送工具，或将输出方式设为 `file`。本插件不接管 QQ 登录。
- **音频生成成功但目录被拒绝**：把 `outputDir` 设为 OneBot 已允许的媒体目录。
- **重复工具名**：停用原有唱歌入口或修改本插件 `toolName`。不要同时让模型看到两个功能相同的点歌入口。
- **音准或歌声比例不通过**：选更清晰、确实有歌声的片段；不会绕过检查发送失败结果。
- **模型下载中断**：再次运行安装器，成功校验的文件不会重下。不会把未校验的 `.part` 文件当成模型。
- **Seed-VC 目录被自己修改过**：安装器会停止，先备份并移开该目录再重新安装，避免覆盖修改。

`jobs/` 保存本地诊断，`requests/` 保存调用与结果，缓存目录保存音频。它们都不应提交到公共仓库。

## 与生图共用 GPU

同一 DSH 进程内使用既有 `Symbol.for('dsh.localGpuQueue.v1')` 队列，采用同一协议的绘图插件可共享串行调度。独立后端还通过文件锁避免同一数据目录被多个转换任务并发写入。

外部 ComfyUI 不共享 DSH 队列时，可以配置 `comfyUrl`：检测到正在绘图则停止本次唱歌，不终止别人的任务。只有明确设置 `unloadComfy: true` 时，空闲模型才会被释放。

## 选择唱法与缓存

| 工具参数 | 行为 |
|---|---|
| `mode: full` | 整首；不附加起点或 duration |
| `mode: opening` | 从起唱处开始，唱第一遍副歌前的开头段；没有可靠副歌定位时取开头完整歌词片段 |
| `mode: chorus` | 可靠定位到的副歌；无法定位则报错 |
| `mode: opening_to_chorus` | 从起唱处到第一遍完整副歌结束，包含副歌；无法可靠定位时明确失败 |
| `mode: long` | 默认约 90 秒；优先用已有歌词时间轴选段，没有时间轴时直接取普通片段，不先转写整首，也不自动延长到完整副歌 |
| `mode: from` | 指定秒数或歌词；不填 duration 时唱到结尾 |
| `mode: excerpt` | 默认普通片段约 45 秒；可指定更长时长 |

时长至少 5 秒，无 90 秒上限。完整转换通过 QA 后，保存原时间轴母带、来源身份、音色指纹和文件哈希。剪片段前校验这些记录；换音色、换版本或缓存损坏时不会错误复用。播放版可以缩短长间奏，母带始终保留完整时间线。

缓存剪切通常不用 GPU；第一次歌词或副歌定位仍可能运行 CPU Whisper。已定位的音轨时间轴随后可复用。

省略歌手时，只有明确唯一的整首缓存才会被采用；同名不同版本不会被随意替换。开头、长片段等结构选择同样优先使用完整母带。

## 原唱与音域

点歌无需必须填写歌手。自动查找会优先确认原唱；B 站标题缺少歌手时会补看简介。只能找到翻唱或身份不明确的版本时，工具返回候选，先询问用户；用户确认后传入对应 `source_url`。明确指定的链接代表用户选择的版本，不再要求其标题包含歌手。

自动音域调整只在两种结果间选择：保留原音高，或整体升 12 个半音。需要足够的有效歌声、源音域明显偏低、低音占多数，且升八度确实更接近参考说话音域。不会把每个音单独改到说话音高；旋律相对关系保持不变。音准比较会计入这一次整体移调，其他偏音仍会被检查。

更新转换器会改变音色指纹，避免新点歌自动复用旧转换结果。用户明确选择的缓存编号仍直接播放该录音；刷新旧曲库需要重新转换和校验，不应只改指纹。

## DSH 插件页（0.3.0）

| 字段 | 默认 | 用途 |
|---|---|---|
| referenceAudio | 留空 | 参考录音绝对路径；空值沿用 backend.json |
| excerptSeconds / longSeconds | 45 / 90 | 普通/加长点歌的默认秒数，明确时长和完整版优先 |
| autoOctave | true | 新合成自动判断0或+12半音；关闭保留原曲音域 |
| voiceGain / musicGain / harmonyGain | 1.25 / 0.55 / 0.8 | 人声、伴奏、独立和声倍率 |
| shortenGaps | true | 保守缩短长间奏 |

插件页设置覆盖对应后端值，仅传给子进程，不重写 backend.json。默认时长仅影响普通和加长模式；参考音色、音高与混音设置纳入成品缓存标识。已有歌单可照常播放；选旧缓存不会自动套用新混音设置。`leadPython` 由安装器写入后端配置，指向独立 `.venv-lead` 环境。
